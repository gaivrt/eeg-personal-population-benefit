# 新任务与历史任务的对齐（2026-09-27）

本轮仍是X0，不运行实验。此复核响应用户对训练量和4卡限制的质疑，以及“回顾过去、说明做什么和为什么”的要求。原任务要补的是**跨基础模型的诊断证据**，并未要求重启全部方法探索。

## 初版为什么错

1. 没有先用历史配置和Slurm实绩校验预算。C每候选3,000步，W续训上限为所选初训步数的3倍；我却自行设200采样epoch，每候选约34,000步，再叠加未经实测的吞吐和100%验证开销，得到过大的卡时区间。
2. 把“保存验证曲线、定义收敛判据”误解成“必须训练到所有曲线平坦才停”。原W已经明确早停与平台是两件事；补记录不等于扩大训练预算，更不能承诺有限训练一定收敛。
3. 无依据设4卡并发，又把这个数转换成几周的顺序排期。历史W是13卡，每卡通常两个运行；B/B2已有16卡。新任务只规定每作业一卡，没有规定4卡上限，也没有规定每卡只能放一个fold/seed进程。
4. 将“按模型×数据集报告”误作重新定义主检验的理由，新增跨模型6/12/8项家族；还混淆了C的初训选择与W的续训选择，并给任务近邻添加了原本仅静息诊断使用的前置条件。
5. 将有明确来源的审计结论、我自行增加的规则、未计时的资源假设一起写成“X0完成”。这掩盖了资源估算和逐组合日期仍需校准的事实。

这些问题属于执行和复核错误，任务范围本来已经明确；不是用户没有提供足够信息。v1.26撤销上述设定，历史结果与历史判定不改动。

## 本次具体做什么，为什么

**X0先把可比性写清楚。** 固定两模型官方预训练权重；核查全部五库的预训练重合；列明采样/滤波/缩放/通道、层数和适配位置。REVE重合Dreyer/Cho/Lee，LaBraM重合PhysioNet，按事先选择保留并单列。这些是解释复现结果所需的来源与接口审计，不是新方法。

**X1核心每个新模型执行原25个折/种子运行。** 起步三库联合训练共享B0/G，每库分别报告；两个模型共50个折/种子运行，不是六个组合各训练25套独立群体模型。每运行包括：

1. 冻结新骨干，按原linear/MLP128与原lr网格训练B0任务头。新骨干特征不同，旧CBraMod头不能直接加载。
2. 全层群体LoRA r8加任务头。骨干始终冻结；新模型的层数/维度不同，需要重新拟合共享适配器。初训只用原lr={3e-4,1e-3}、候选步数={1,000,3,000}，按验证增益中位/均值及原同分规则选定。只从选定点按W规则续训，额外最多所选步数3倍，CE早停；不强制跑满。
3. 在冻结G上加零初始化个人LoRA，用本人前半标签拟合，后半计分；原20/60步、lr/wd网格只由验证被试选择。同一批个人参数用于本人/交换，不为每个供体重训。
4. 原少样本时间前缀和各n验证选择程序，报告相对G的收益、全前半恢复比例、个体下降与种子变化。模型×库完成即更新结果表。

逐epoch保存验证损失、accuracy、BA和分库/逐人数据；分别记录初训所选步数、续训实际步数、最终所选步数。恢复原合并主判定和分库描述，日志密度不扩大候选集合，新增准确率平台字段不改变训练预算。结果未达平台就如实写未确认收敛。

**必要差异必须披露。** 用户本次指定普通群体LoRA r8，历史CBraMod的G却是C的8个r8共享基和上下文训练所得；两者不是相同群体参数化/目标。这里复现诊断关系，不能称为只替换骨干的单因素消融。按本任务不重做生成器，也不擅自重训CBraMod去消除此差异。

核心完成后停止报告。随后扩展仍按FiLM→无标签近邻→Lee/BNCI→M1/R2；每子阶段停止。不存在因为本轮“训练更多”就重新启动C4、M2或新的方法设计。

## 算力与尚未完成项

本地已保存Slurm回执去重为**167.44 GPU卡时**，其中C4约40.53、M约41.72，二者合计82.25卡时，而本次核心均不重做。这支持用户对初版预算的质疑。统计含回执中的失败，按GPU分配时间计，未把同卡两个worker重复相加；它不是对集群全部作业的补查。[逐作业回执与来源](cross_model_audit_2026-09-27/historical_gpu_accounting.json)。

撤销420–1350核心卡时、700–2290全部卡时、4卡上限及据此推算的日期。新模型的真实吞吐/显存尚未测量，不能直接承诺它们合计也少于200卡时。后续以固定工作量和小规模训练/验证计时校准；总并发由可用3090及用户确认确定，同卡进程数按显存/吞吐决定，不自行压到4卡。12月10日截止和核心优先保留。

当前审计与协议已修正，**总卡时和逐模型×库完成日期待校准，不能标为X0全部交付完毕**。X0仍不跑计时实验；先完成可复核的X1工程入口，再按项目要求说明新GPU批次用途、总卡数、预计耗时并取得确认。本次复核没有运行新实验或提交GPU作业。
